# Отчет по домашнему заданию №1: Вариант «Управление проектами» (Project Management)

## Задание 1. Концептуальная модель
В данной системе управления проектами выделены следующие основные сущности:

1. **Project (Проект)** — основной контейнер работ. Содержит информацию о названии проекта, датах начала и дедлайне.
2. **Task (Задача)** — конкретная рабочая единица внутри проекта. Наследует принадлежность к проекту и имеет свой статус, приоритет и оценку времени.
3. **Employee (Сотрудник)** — участник команды, который может создавать проекты, руководить ими или выполнять назначенные задачи.
4. **Assignment (Назначение / Исполнители)** — связующая сущность «многие ко многим» между сотрудниками и задачами (так как на одну задачу можно назначить несколько исполнителей, а сотрудник может выполнять несколько задач).
5. **Comment (Комментарий)** — текстовые заметки и обсуждения, которые сотрудники оставляют к конкретным задачам для коммуникации.
6. **Status (Статус)** — справочник возможных состояний задач.

### Схема связей:
- Между **Project** и **Task**: связь *один ко многим* (1:N). Один проект включает много задач, но каждая задача принадлежит ровно одному проекту.
- Между **Project** и **Employee (Сотрудник)**: связь *один ко многим* (1:N). Один сотрудник может руководить несколькими проектами.
- Между **Task** и **Employee** через **Assignment**: связь *многие ко многим* (M:N).
- Между **Task** и **Comment**: связь *один ко многим* (1:N). У одной задачи может быть много комментариев.

## Задание 2. Логическая модель

В логической модели определены следующие атрибуты, первичные (`PK`) и внешние (`FK`) ключи:

- **Project**: `project_id` (PK), `name`, `start_date`, `deadline`.
- **Status**: `status_id` (PK), `name`.
- **Task**: `task_id` (PK), `project_id` (FK), `status_id` (FK), `title`, `estimated_hours`.
- **Employee**: `employee_id` (PK), `first_name`, `last_name`, `email`.
- **Assignment**: `assignment_id` (PK), `task_id` (FK), `employee_id` (FK).
- **Comment**: `comment_id` (PK), `task_id` (FK), `employee_id` (FK), `content`, `created_at`.

### Кардинальность и типы связей:
- **Project 1 : N Task** (неидентифицирующая связь): один проект содержит много задач.
- **Status 1 : N Task** (неидентифицирующая связь): один статус может быть у множества задач.
- **Task M : N Employee** через промежуточную сущность **Assignment**: одна задача может выполняться несколькими сотрудниками, а сотрудник может иметь много задач.
- **Task 1 : N Comment** (неидентифицирующая связь): к одной задаче можно оставить множество комментариев.

## 3. Физическая модель

В рамках физической модели был написан воспроизводимый SQL-скрипт для СУБД **PostgreSQL**. 

### Особенности скрипта:
- Используется автоматическая генерация первичных ключей (`SERIAL PRIMARY KEY`).
- Применены ограничения целостности: `NOT NULL`, `UNIQUE`, `CHECK`.
- Настроены внешние ключи (`FOREIGN KEY`) с правильным поведением при удалении (`ON DELETE CASCADE` / `ON DELETE RESTRICT`).
- Для ускорения выборки данных по связям созданы индексы (`CREATE INDEX`) на все внешние ключи.
- Скрипт является полностью воспроизводимым: в начале файла предусмотрено безопасное удаление старых таблиц (`DROP TABLE IF EXISTS ... CASCADE`).

*Сам исполняемый файл скрипта сохранен в корне папки первого задания под именем `01_create_tables.sql`.*
