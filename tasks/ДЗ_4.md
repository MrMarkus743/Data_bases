### Блок 1. Базовая фильтрация, даты и интервалы

#### Задача 1. Выполненные рейсы из Москвы
* **Формулировка:** Выбрать все выполненные рейсы (`status = 'Arrived'`) из московских аэропортов за август 2017 года.
* **Выводимые поля:** номер рейса (`flight_no`), код аэропорта вылета (`departure_airport`), фактическое время вылета (`actual_departure`).
* **Сортировка:** по возрастанию фактического времени вылета.

#### Задача 2. Рейсы с критическим опозданием
* **Формулировка:** Найти рейсы, прибывшие с опозданием более чем на 2 часа (`actual_arrival > scheduled_arrival + INTERVAL '2 hours'`).
* **Выводимые поля:** номер рейса (`flight_no`), плановое время прибытия (`scheduled_arrival`), фактическое время прибытия (`actual_arrival`), опоздание в минутах (`ROUND(EXTRACT(EPOCH FROM ...) / 60.0, 1)`).
* **Сортировка:** по убыванию величины опоздания (самые большие задержки сверху).

#### Задача 3. Статистика рейсов серии PG04
* **Формулировка:** Для рейсов с номерами, начинающимися на `PG04` (диапазон `PG0400`–`PG0499`), посчитать количество выполненных рейсов по каждому номеру рейса.
* **Выводимые поля:** номер рейса (`flight_no`), количество выполненных рейсов.
* **Сортировка:** по номеру рейса.

#### Задача 4. Средняя задержка по аэропортам вылета
* **Формулировка:** Для каждого аэропорта вылета рассчитать суммарное число рейсов и среднее опоздание прибытия в минутах.
* **Фильтрация (`HAVING`):** оставить только аэропорты, из которых отправлено более 500 рейсов.
* **Сортировка:** по убыванию среднего времени опоздания.

#### Задача 5. Топ-10 самых дорогих проданных билетов

* **Сортировка:** по убыванию стоимости билета.

#### Задача 6. Реестр всех аэропортов маршрутной сети

#### Задача 7. Топ-5 пассажиров по объему трат

* **Сортировка:** по убыванию общей суммы трат.

### Блок 3. Продвинутая аналитика, Sargability и оптимизация планов

#### Задача 8. Многоуровневые итоги через `ROLLUP`
* **Формулировка:** Посчитать помесячную выручку от продажи билетов за 2017 год с формированием строки общего итога в рамках одного запроса с помощью группировки `ROLLUP`.
* **Требования к фильтрации:** 
  - Оставить в выборке только месяцы с выручкой более 10 млрд рублей (`HAVING`).
  - Обеспечить сохранение строки общего итога («ИТОГО» со значением `NULL` / `GROUPING = 1`).
* **Анализ `EXPLAIN ANALYZE`:** Объяснить механизм применения `HAVING` к иерархическим строкам `ROLLUP` и причину прохождения итоговой строки через фильтр.

#### Задача 9. `LEFT JOIN` и условная агрегация
* **Формулировка:** Для каждого аэропорта прибытия посчитать число фактически прибывших рейсов (`status = 'Arrived'`), включая аэропорты с нулевым числом прибытий.
* **Выводимые поля:** код аэропорта (`airport_code`), название аэропорта (`airport_name`), число прибывших рейсов.
* **Требование к эксперименту:**
  1. Выполнить корректный запрос с условием статуса в блоке `ON`.
  2. Продемонстрировать контрольным запуском, что произойдет с выборкой при переносе условия в блок `WHERE`.
  3. Обосновать недопустимость конструкции `COUNT(*)` при сохранении пустых групп и объяснить роль физического узла `Hash Right Join` в плане выполнения.

#### Задача 10. Оптимизация предикатов (Sargability)
* **Формулировка:** Найти все рейсы, выполненные (`status = 'Arrived'`) в выходные дни (суббота и воскресенье) в августе 2017 года.
* **Требование к эксперименту:**
  1. Написать неоптимизированный запрос с вычислением функции над столбцом (`EXTRACT(DOW FROM ...)` или `TO_CHAR(...)`).
  2. Написать оптимизированный (Sargable) запрос с использованием прямых диапазонов дат и полуоткрытых интервалов.
  3. Сопоставить планы `EXPLAIN (ANALYZE, BUFFERS)` обоих вариантов и обосновать разницу в затратах (`cost`, `actual time`, дисковые страницы).

#### Задача 11. Оптимизация отрицания (Anti-Join)
* **Формулировка:** Найти все рейсы, на которые не было продано ни одного билета бизнес-класса (`fare_conditions = 'Business'`).
* **Требование к эксперименту:**
  1. Реализовать запрос с использованием предиката `NOT IN`.
  2. Реализовать запрос с использованием предиката `NOT EXISTS`.
  3. Сопоставить планы выполнения, объяснить появление узла Anti-Join и описать опасность конструкции `NOT IN` при потенциальном наличии значений `NULL` во вложенной выборке.

#### Задача 12. Индексное сканирование (Index Only Scan)
* **Формулировка:** Рассчитать количество рейсов по каждому статусу:

* **Требование к эксперименту:**

     ```sql

     ```
  3. Выполнить регламентное обслуживание карты видимости: `VACUUM bookings.flights;`.
  4. Снять повторный план выполнения.
  5. Обосновать переход оптимизатора на `Index Only Scan` (`Heap Fetches: 0`) со ссылкой на механизм Visibility Map в PostgreSQL.
